# Offline render tests

The main test suite is `npm test` (see TESTING.md in the app folder), which plays the real app with real touches.
These older tools render the app's audio graph into an `OfflineAudioContext` through test hooks, which makes
them fast and exactly repeatable: they are kept for sound design (timbre measurements, the LEVEL calibration).
Note that `pitch.js` sets key and scale through a hook rather than the on-screen controls, so it cannot catch a
control that fails to reach the sound; the live pitch check in `npm test` does. This file is generated by
`node tests/report.js` from the JSON the tests write to `tests/results/`.

## Running the tests

Needs Node 18+ and Playwright's Chromium (`npx playwright install chromium` if it is not already installed).

```sh
cd tests && npm install          # once: installs Playwright
npm run pitch                    # key x scale test, every melodic instrument (about 3 minutes)
npm run instruments              # tuning, timbre, bowing, breath, stops, strums, release fades, note limit, recording
npm run horn                     # French horn crackle check (clipping, added distortion, bursts, level jumps)
npm run loudness                 # peak and RMS of every instrument and pad
npm run calibrate                # re-derive the LEVEL trims in index.html (only after changing a sound)
npm run calibrate -- --only=Trumpet,Synth   # calibrate (or measure) only the sounds whose name starts so
node horn.js horn-before.json ../before.html  # the crackle check on any version of the app
npm run baseline -- ../index.html results/after.json   # same UI gestures on any version of the app
npm run report                   # rebuild this file
```

## How the harness works

- `tests/lib/browser.js` opens `index.html` in headless Chromium and, before the app's script runs, swaps
  `AudioContext` for an `OfflineAudioContext` (48 kHz, stereo). Timed actions run at exact audio times by suspending
  the offline render, so a test can press a key at 0.3 s and lift it at 1.05 s.
- Notes are played the way a person plays them wherever that is possible: synthetic pointer events on the
  piano keys, flute, horn, trumpet and sax cells, harmonica holes, the organ and synth keys, the xylophone bars, the
  bowed and bass fingerboards, and the real chord buttons on the guitar and rhythm guitar. Bow strokes, whose speed comes from event timestamps, go through the same input functions the touch
  handlers call (`bwDown` / `bwMove` / `bwTick`) with explicit times. These hooks only exist when the harness sets
  `window.__PB_TEST__` before the page loads.
- Expected notes come from `tests/lib/reference.js`, written from the musical definitions rather than copied from
  the app, so a pass means the app's pitches and its labels both agree with music theory.
- Pitch (`tests/lib/analysis.js`): YIN finds the period, then the power-weighted mean frequency of three harmonics
  above 300 Hz is taken over the whole window from a Hann-windowed DFT. For detuned oscillator stacks (horn,
  strings) and vibrato this is the average pitch a listener hears; on a clean tone it is exact to well under 0.1 cent.
- Peak is the sample peak at the app's output, in dBFS. RMS is measured while the note sounds: from its start to
  the last sample within 20 dB of its peak (reverb tail excluded, at most 1 s). "Phone-band RMS" is the RMS above
  200 Hz (12 dB/octave high-pass), roughly what a phone speaker can reproduce.
- Every render is repeatable. `Math.random` (noise, humanising, oscillator start phases) is replaced by a seeded
  generator that restarts with each audio context, and work the app defers to the next animation frame (pointer
  moves, breath, bow) runs straight after the action that queued it, at that action's audio time. Measurements that
  depend on how detuned copies of a note happen to beat (string and horn attack, brightness) take the median of five
  seeds.
- A new Web Audio compressor starts fully clamped and takes about 0.2 s to open, so every measured note starts
  0.3 s into the render. The app now bridges that window itself (see "First note after start-up" below).

## What was wrong (measured on the version before this change)

- **Key and scale.** Piano and guitar had no key or scale at all. The violin and cello ignored the key: the same
  finger position played 338.48 Hz in C and 338.48 Hz in D (cello 123.09 / 123.09 Hz),
  because the key only moved the guide marks. The harmonica ignored the scale. Flute and horn did follow the key,
  but every instrument kept its own copy of the scale tables, and only six of the ten scales existed.
- **Violin and cello.** The tuning itself was right (open strings measured 196.1, 294.1, 440.3, 659.3 Hz and 65.4, 98.0, 147.0, 220.1 Hz).
  They sounded alike because both used the same two-sawtooth recipe through similar filters, and a cello's low
  register (65-220 Hz) is mostly below what a phone speaker plays, so what was left sounded like a violin.
- **Loudness.** The master chain was volume 0.8 into a default `DynamicsCompressor` (threshold -24 dB, ratio 12,
  30 dB knee), which squashed everything. Per-sound levels were never balanced: tabla Te and Ti peaked around
  -25 dBFS, the drum pad closed hat at -15 dBFS with a mid hit. Kicks, toms and the bayan had 75-80% of their
  energy below 200 Hz, which a phone speaker barely reproduces. A new compressor also starts clamped, so the
  first note after the app woke up came out about 10 dB quiet.
- **French horn.** Two sawtooths and a sine through a bright filter and a tanh distortion: buzzy, nothing like a horn.

## French horn crackle

`tests/horn.js` renders all 15 horn notes at soft, medium and full breath (0.3, 0.65, 1), plus a legato slide over
the whole range and a breath swell, twice each: once normally and once with the master routed straight to the
output, so the signal going into the limiter can be compared with what comes out. Pass: no sample at or above 0.99,
less than -50 dB of distortion added by the master stage, no burst of energy above 7 kHz more than 14 dB over the
note (held part, attack and release), and no jump over 6 dB between 20 ms frames.

| Measure (worst case over all notes and gestures) | Before | After |
| --- | ---: | ---: |
| Samples at or above 0.99 (output / before the limiter) | 0 / 0 | 0 / 0 |
| Distortion added by the master stage (dB below the signal) | -19.7 | -80.7 |
| Peak going into the limiter (dBFS) | -0.6 | -6.7 |
| Peak at the output (dBFS) | -1.0 | -1.6 |
| High-frequency burst while held (dB over the median) | 11.7 | 12.1 |
| High-frequency burst at attack and release (dB) | 10.8 | 11.9 |
| Largest level jump between 20 ms frames (dB) | 3.8 | 3.3 |
| THD of the tone (range over notes, %) | 50-132 | 9-123 |

**Cause.** Nothing clipped, but at full breath the horn reached the limiter at about -0.6 dBFS, 5 dB over its
threshold, so the limiter (ratio 20) and the soft ceiling behind it were reshaping every cycle: up to 20 dB below
the note, which is audible as a grainy, lo-fi edge. The tone itself, its envelopes and the filter moves were
smooth (no bursts or level jumps beyond the beating of its detuned copies).

**Fix.** The horn's level now follows breath on a gentler curve (35% to 100% rather than in straight proportion), its trim is
calibrated at full breath to peak at -4.5 dBFS (trumpet, sax and the organ with all stops are calibrated the same
way), its own shaper oversamples 4x, and a gentle tanh soft clip sits after it, so the loudest note reaches the
limiter about 7 dB below full scale. Gain and filter changes already used `setTargetAtTime` ramps and the
filter already tracked pitch, so those were kept. Distortion added by the master stage fell to -81 dB.

## Master chain

`master volume -> limiter (DynamicsCompressor: threshold -6 dB, ratio 20, 2 ms attack, 150 ms release) -> make-up
gain (+2 dB; the browser adds its own make-up of about +3 dB) -> soft ceiling (linear to -2 dBFS, never above -1 dBFS)`.
A single note at the default volume passes through untouched (+4.8 dB overall). Chords and stacked hits are held
down by the limiter, and the ceiling catches anything faster than its attack; the limiter test above shows every
stress case peaking at -1.0 dBFS with no clipped samples, even at 150% volume. The master volume slider in
Settings runs 0-150%, defaults to 100%, and is remembered.

**First note after start-up.** A new compressor starts fully clamped and needs about 0.2 s to open, which made the
first note after the app woke up about 10 dB quiet. For the first 0.3 s the app now sends audio through a plain gain
path with the same +4.8 dB, then crossfades to the limiter.
